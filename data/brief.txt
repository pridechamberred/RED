Build Prompt: Networking Group Activity App

Build a clean, modern, mobile-first web application for a business networking group.

The app is an extremely simple activity-recording system. Its purpose is to allow members to quickly record networking activity and allow administrators to see all activity across the group. The priority is a clean, beautiful and user-friendly UX.

IMPORTANT: This is an MVP. Do not add features that are not explicitly requested below. Prioritize simplicity, speed, and an excellent mobile UX over feature richness.

1. Core UX PRINCIPLE

The application should feel Google-like rather than like a traditional business-management application.

The user should not have to navigate through menus to find a person and then choose an action.

The primary interaction on the homepage should be:

Who are you looking for?

A large search box allows the user to start typing a member’s name.

As they type, matching members appear immediately.

When the user selects a person, show a very simple action screen:

What would you like to record?

🤝 Record a Vous

🎁 Pass a Referral

💰 Report a Done Deal

The selected person should automatically be associated with the action wherever appropriate.

For example:

User types “Sarah”

Sarah Smith appears

User taps Sarah Smith

Three large buttons appear:

Record a Vous

Make a Referral

Report a Done Deal

User completes the minimum information required.

The record is saved.

Show a simple success confirmation.

The goal is that a member can record an activity in seconds, without having to understand the application.

2. USERS

There are three roles:

USER

A networking-group member who can:

Record Vous / 1:1 meetings with another user

Record passed referrals to another user

Record done deals from another user

Record own volunteering hours

Record own attendance at events

NOTE: There are currently five sub-groups within the networking group, each user belongs to one of these sub-groups.

ADMIN

An administrator who can:

See all data recorded by all users in their own sub-group

Filter and search the data in their own sub-group

View individual member activity in their own sub-group

Admins do not need complicated management functionality in this MVP.

SUPER-ADMIN

An administrator who can:

See all data recorded by all users across all sub-groups

Filter and search the data across all sub-groups

View individual member activity across all sub-groups

15. AUTHENTICATION

Users should log in securely.

Use Supabase authentication.

Once logged in, the application should know:

Who the user is

What sub-group they are part of

Their member record

Whether they are an admin

Users should only be able to create records as themselves.

Users should be able to see their own activity.

Admins can see all activity.

Implement appropriate Supabase Row Level Security policies.

Likewise:

Report Done Deal

should already know that the referral came from Sarah Smith.

Search should be forgiving and use search-as-you-type.

If the user enters:

“Sarah”

show Sarah Smith.

If they enter:

“Smith”

Confirmation should be immediate

The app should make this interaction incredibly easy:

“I just had a 1:1 with Sarah.”

Open app.

Search:

Sarah

Tap:

Sarah Smith

Tap:

Record a Vous

Tap:

Record Vous

Done.

Similarly:

“I just gave Sarah a referral.”

Search Sarah → Pass a Referral → enter referral information → Send Referral → done.

And:

“Sarah sent me a customer who just bought $2,000 of services.”

Search Sarah → Report a Done Deal → enter customer/value/type → Record Done Deal → done.

The user should never have to think about where information belongs in the application.

Build the UI around these real-world interactions rather than around database entities.

The application should feel like a quick activity recorder, not a management system.
